# DSWeave · 产品与计划文档

> 项目名：**DSWeave**。Weave＝织造：把一批文件织成一个**可交互的 3D 知识场景**。
> 文档版本：v0.4 ｜ 状态：评审中
> 定位：**空间化知识引擎**——领域聚焦"知识库管理 + 自动研究（auto research）"，但产物是 **3D 沉浸式 HTML（WebGL）**，支持 gltf 等模型。

> **架构演进（2026-06）**：可靠性策略已从「数据驱动：Agent 只产 SceneSpec，预构建 R3F Player 渲染」改为「Agent 直接写自包含 HTML，Host 注入 model-viewer 运行时 + 内联 asset://{nodeId} 资产字节兜底」。产物仍离线自包含、内容寻址可缓存；@dsweave/player 包与 SceneSpec 契约已移除。下文据此更新。

---

## 1. 一句话定义

**DSWeave 是一个"拖入文件 → Agent 理解 → 产出 3D 沉浸式知识场景（HTML/WebGL）"的可视化工作流引擎。**

用户做三件事：
1. **拖入文件**（gltf 模型 / md / pdf / txt / html / 图片 / csv-json …）——这是仅有的"实体输入"。
2. **写语义文字**——给连线写一句话（资料/模型之间的关系），给输出写一句话（想要的 3D 场景风格与组织）。
3. **点开始**——一个通过 **ACP** 连接的 AI Agent **读懂这些文件**，产出一个**受限形态**的 3D 知识场景。

> 这就是"不一样的引擎"：**即便目标产物是 HTML，它也是 3D 的** —— 一个 WebGL/three.js 的可交互页面，gltf 模型作为一等公民嵌入场景，知识被空间化地组织，可旋转、漫游、点击热点查看对应资料。

> 三条铁律：
> - **输入只有文件**；核心功夫＝把文件**解析好、表示好、作为上下文喂好**（文档解析 + gltf 理解）。
> - **输出是受限菜单**，不是任意自然语言；自然语言只管"软细节"（风格/布局/文案）。旗舰输出 = **3D 沉浸页 `scene.html`**。
> - **领域聚焦**：知识库管理 + auto research，用 3D 空间表达做差异化。

---

## 2. 核心引擎：文件理解与上下文工程（产品的主价值）

DSWeave 的护城河有两块：① **把一堆杂乱文件变成 Agent 能用好的上下文**；② **把 gltf 模型理解成可被编排进 3D 场景的素材**。

| 文件 | 要解析/表示出什么 | 手段 |
| --- | --- | --- |
| **gltf 模型** | 多角度渲染图 + 网格/材质/动画/包围盒元数据 | 离屏渲染（three.js/model-viewer）+ 解析 glTF JSON |
| md / txt | 正文 + 结构 | 直接读 + 分节 |
| pdf | 正文 + 标题层级 + 图表 | pdf 解析（pdfjs/pdf-parse） |
| html / 网页 | 正文抽取（去噪） | readability |
| csv / json | schema + 数据摘要 | 解析 + 统计摘要 |
| 图片 | OCR + 视觉描述 | OCR / 视觉模型 |
| （后续）video/audio | 创作域，暂不在 MVP | —— |

在文件之上再做**上下文工程**：
- **分块（chunking）** + **摘要**：长文档切片并生成层级摘要。
- **检索（retrieval）**：知识库大时不一次性塞满上下文，按相关性选片喂给 Agent。
- **引用可追溯**：产物里的论断能回指到来源文件/段落。

> 文件理解 + 上下文工程的质量＝产品上限，单列为一等技术问题（见 `02-technical-design.md`）。

---

## 3. "节点图"是什么（澄清）

- **节点 = 一个文件**（用户拖入，可以是 gltf 模型或文档）。
- **边 = 一句语义文字**（资料/模型间关系，如"把这份说明书的章节作为这个模型各部件的热点解说"）。
- **输出节点 = 选一种输出类型 + 一句软细节描述**（如：3D 场景，"暗色科技风、模型居中可旋转、文档以浮窗热点呈现"）。

没有隐藏算子、没有类型系统要用户操心。

---

## 4. 受限输出（本次核心收敛）

**输出 = 从能力注册表派生的固定菜单**，每种输出都对应一个真实存在、可执行、可测试、可缓存的 Host 能力。自然语言只填"软槽"。

| 输出类型 | 产物 | 何时做 | 说明 |
| --- | --- | --- | --- |
| `scene.html` | **3D 沉浸式 HTML（WebGL）** | **MVP 首发** | Agent 直接写自包含 HTML（用 `<model-viewer>` 预览、`asset://{nodeId}` 引用源文件）；Host 后处理注入运行时 + 内联资产字节 → 自包含单文件，嵌 gltf + 文档热点，可旋转/漫游/点击 |
| `report.html` | 平面自包含 HTML | 备选/降级 | 不需要 3D 时，Agent 按风格提示自由写偏 2D 报告的 HTML |
| `app.react` | React 工程（R3F） | 紧随其后 | 以工程/dist 形式交付复杂交互的 React 应用 |
| `custom` | 尽力而为 | 后期开放 | 实验性、不保证成功，默认隐藏 |

> **可靠性靠 Host 物理兜底**：**Agent 直接撰写自包含 HTML**——用 `<model-viewer>` 预览模型、用 `asset://{nodeId}` 引用源文件，专注内容组织与风格而非环境装配。**Host 是唯一兜底**：后处理时把经测试的 model-viewer 运行时注入页面，并把 `asset://{nodeId}` 内联为 data URI 资产字节。把"会出错的环境/资产装配"交给 Host 确定性后处理 → 产物离线自包含、内容寻址可缓存、一定跑得起来。

## 5. 目标用户与典型场景

**用户画像**：研究者、产品/设计、教育/培训、展陈/营销——手里有资料（也许还有 3D 模型），想要一个比 PPT/报告更有表现力的可交互 3D 知识产物。

**典型场景**（MVP 输出 `scene.html`）：

1. **★ 产品 3D 知识页**：拖入 `产品.gltf` + 若干说明文档 ──"模型居中可旋转，把各章节做成对应部件的点击热点"──> 3D 沉浸页。
2. **3D 文献/资料展厅**：拖入若干 md/pdf（+ 可选模型）──"围绕『X』做综述，以空间展厅方式陈列、突出共识与分歧"──> 3D 知识场景。
3. **教学/拆解讲解**：拖入机械/分子 `model.gltf` + 讲义 ──"按讲义步骤分步高亮部件并配解说"──> 可交互 3D 教学页。
4. **轻量降级**：不需要 3D 时选 `report.html` ──"对比 A/B/C 给选型建议"──> 平面 HTML 报告。

> 后续解锁 `app.react`（R3F）后：可筛选、可状态切换的复杂 3D 知识浏览器。

## 6. 产品范围（In / Out）

### 6.1 MVP 做什么

- 画布：拖入文件 → 带**预览**的节点（gltf 3D 预览、md/pdf/txt/html/image/csv-json）。
- 文件理解：Host 解析文档 + 渲染/解析 gltf → 分块/摘要 + 模型表征。
- 连线：边上写自然语言语义。
- 输出节点：从受限菜单选 `scene.html`（3D）+ 写软细节。
- 一键执行：序列化整图 → ACP 发给 Agent → 执行（危险操作审批）→ 产出 3D HTML。
- 执行态可视化 + 产物 iframe 预览（3D 可交互）+ 引用可追溯。
- 工作流存取：`.flow.json`。

### 6.2 暂不做

- `app.react`（R3F 复杂交互）与 `custom` 输出（MVP 后）、video/audio 文件、多人协作、云端、账号计费、移动端。
- 外部联网检索（auto research 的"上网"能力）列为后续，受 permission 约束；MVP 先基于"用户提供的文件"做研究。

## 7. 成功标准

- **理解力**：能正确解析 md/pdf 等文档，并把 gltf 模型理解成可编排素材（渲染图+元数据）。
- **可靠性**：选 `scene.html` 后稳定产出可在浏览器打开、能加载 gltf 并交互的 3D 页面。
- **差异化**：产物是 3D 可交互场景，明显区别于普通报告/PPT 生成器。
- **可追溯**：场景里的论断/解说能回指来源文件/段落。
- **架构健壮**：更换 Agent 实现（Mock/自建/外部）不需改前端。
- **可复现**：`.flow.json` 复跑结果一致（命中缓存）。

## 8. 里程碑与路线图

| 阶段 | 代号 | 目标 | 验收 |
| --- | --- | --- | --- |
| M0 | 地基 | Monorepo + 工具链 + 类型骨架 | `pnpm build` 全绿，前端起空页 |
| M1 | 画布 | 文件拖入 + 预览(gltf 3D + 文档类) + 连线 + IR 存取 | 搭出"gltf+文档→scene.html"图并存取 |
| M2 | 连接 | ACP 打通（前端↔Host↔Mock Agent） | 点 Start 收到 Mock 流式 update |
| M3 | 文件理解 | 文档解析 + 分块/摘要/检索 + **gltf 渲染/元数据理解** | Agent 能基于文档作答/引用，并描述模型外观/部件 |
| M4 | 主竖切 | `scene.html` 能力（Agent 写 HTML → Host 注入运行时+内联资产→单文件） | **拖 gltf+文档、写组织方式，Agent 直接产出自包含 HTML → 可加载模型、可交互、带热点引用的自包含 3D HTML** |
| M5 | 拓展+打磨 | `app.react` 工程交付 + 更多文件类型 + Tauri + 健壮性 | React 3D 工程输出可用；桌面包可运行 |

**节奏**：M0–M2 打通链路；**M3 文件理解（文档+gltf）是核心攻坚**；M4 打通 HTML 产物后处理（运行时注入 + 资产内联）+ 出第一个真实 3D 产物（`scene.html`）；M5 解锁工程交付与产品化。

## 9. 关键风险与对策

| 风险 | 对策 |
| --- | --- |
| 浏览器无法 spawn / 访问本地文件 | Node Host 桥接；预留 Tauri |
| **文件解析/上下文质量不足（核心风险）** | 分块+摘要+检索；引用可追溯；按文件类型迭代 provider |
| **gltf 理解/渲染复杂** | 用 model-viewer/three.js 离屏渲染 + 解析 glTF JSON；先固定几个机位 |
| 生成的 3D HTML 跑不起来/性能差 | Host 注入经测试的 model-viewer 运行时 + 纯文本校验回灌重试 + 约束模型体量 |
| 大知识库塞爆上下文 | 检索式选片，而非全量塞入 |
| 任意输出不可控 | 受限输出菜单（本次收敛） |
| ACP 版本演进 | protocol 层封装隔离 |
| Agent 执行任意命令 | 沙箱工作目录 + 危险操作 permission 审批 |

## 10. 关键决策（已确认 ✅）

1. **名称**：✅ DSWeave。
2. **定位**：✅ **空间化知识引擎**——产物是 **3D 沉浸式 HTML（WebGL）**，支持 gltf 等模型。即便输出 HTML，也是 3D 版本。
3. **运行形态**：✅ Web 前端 + 本地 Node Host（预留 Tauri）。
4. **Agent 来源**：✅ 可插拔（Mock / 自建 / 外部如 Gemini CLI）。
5. **领域聚焦**：✅ 知识库管理 + auto research，用 3D 表达做差异化。
6. **输入**：✅ 仅文件；**gltf 模型与文档并列为一等输入**；核心功夫＝解析/渲染/喂上下文。
7. **输出**：✅ **受限菜单**。MVP 首发 **`scene.html`（3D）**，`report.html` 为 Agent 自由写的 2D 报告降级，次之 `app.react`(R3F 工程)，`custom` 保留但隐藏。
8. **运行时/生成方式**：✅ **Agent 直接写自包含 HTML + Host 注入 model-viewer 运行时/内联 asset:// 资产**；默认交付**自包含单文件 HTML**。
9. **计划预览**：✅ 移除。执行态实时展示 + 仅危险操作审批。
10. **核心攻坚**：✅ **文件理解（文档解析 + gltf 理解）+ 上下文工程 + prompt 工程 + HTML 产物后处理（运行时注入/资产内联）**。
